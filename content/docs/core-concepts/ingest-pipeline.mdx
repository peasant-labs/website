The ingest pipeline is the core of Peasant. When you run `peasant ingest`, your raw AI coding session files pass through nine sequential stages before they become queryable analytics in the database.

## Pipeline Overview

```
DISCOVER → DIFF → FILTER → EXTRACT+WRITE → DB INSERT → INDEX → COMPUTE → CLEANUP → REPORT
```

Each stage feeds into the next. The pipeline is deterministic — given the same input files and configuration, it produces the same output.

## The Nine Stages

### 1. DISCOVER

The pipeline begins by scanning configured provider paths for session files. Each provider adapter (Claude Code, OpenCode) knows where its sessions live and what file format to look for (JSONL, JSON).

The output of this stage is a list of candidate session files on disk.

### 2. DIFF

The discovered files are compared against what is already in the database. If a session has been ingested before and the source file has not changed, it is excluded. This ensures incremental ingestion — only new or modified sessions proceed.

<Callout type="info">
Use `--force` to bypass the diff stage and re-ingest everything, regardless of what is already in the database.
</Callout>

### 3. FILTER

Remaining candidates are filtered based on CLI flags and configuration. Filters include:

- `--since <duration>` — Only sessions newer than the given duration.
- `--session <ids>` — Only specific session IDs.
- `--source-provider <p>` — Only sessions from a specific provider.
- `--include-active` — Include sessions that are currently active (excluded by default).

### 4. EXTRACT+WRITE

Session files are parsed and their contents extracted into Peasant's internal data model. This is where raw JSONL or JSON is transformed into structured session, message, and tool-call records. The extracted data is written to intermediate storage.

### 5. DB INSERT

Extracted records are inserted into the SQLite database. This stage handles schema mapping, conflict resolution, and transactional writes.

### 6. INDEX

After insertion, the pipeline builds or updates indexes on the session data. This includes full-text search indexes and any derived lookup structures that accelerate queries in the dashboard and TUI.

<Callout type="tip">
Use `--reindex` to rebuild all indexes from scratch without re-ingesting session data.
</Callout>

### 7. COMPUTE

Metrics are computed across the newly ingested sessions — token counts, conversation lengths, tool usage patterns, and other derived statistics. These computed values are stored alongside the raw data.

### 8. CLEANUP

Temporary files and intermediate artifacts from earlier stages are removed. The database is optimized if necessary.

### 9. REPORT

The pipeline prints a summary of what was ingested: how many sessions were discovered, how many were new, how many were inserted, and any errors encountered.

Use `--json` to get the report as structured JSON output instead of the default human-readable format.

## Flags That Affect the Pipeline

| Flag | Stage(s) Affected | Effect |
|---|---|---|
| `--dry-run` | All | Run the pipeline without writing to the database |
| `--force` | DIFF | Skip diffing, re-ingest all discovered sessions |
| `--include-active` | FILTER | Include currently active sessions |
| `--session <ids>` | FILTER | Restrict to specific session IDs |
| `--since <duration>` | FILTER | Only sessions newer than the given duration |
| `--source-provider <p>` | DISCOVER | Only use a specific provider |
| `--source-path <path>` | DISCOVER | Override the default source path |
| `--output <path>` | EXTRACT+WRITE | Specify an alternative output path |
| `--reindex` | INDEX | Rebuild all indexes from scratch |
| `--detect-commits` | EXTRACT+WRITE | Detect and associate git commits |
| `--verbose` | REPORT | Print detailed stage-by-stage output |
| `--json` | REPORT | Output the report as JSON |
| `--config <path>` | All | Use an alternative config file |
