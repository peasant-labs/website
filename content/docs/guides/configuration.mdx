Peasant is configured through a YAML file that controls which providers are active, where session data is found, and how the ingestion pipeline behaves.

## Config File Location

The configuration file lives at:

```
~/.config/peasant/config.yaml
```

Peasant respects the `XDG_CONFIG_HOME` environment variable. If set, the config file is located at `$XDG_CONFIG_HOME/peasant/config.yaml`.

<Callout type="tip">
Run `peasant kickstart` to generate the initial config file with sensible defaults. You do not need to create it by hand.
</Callout>

## Configuration Structure

The config file is YAML. Below is an annotated example showing the key sections:

```yaml
# Provider configuration
providers:
  claude-code:
    enabled: true
    # Path to Claude Code session data (JSONL files)
    # Defaults to the standard Claude Code data directory if omitted
    path: "~/.claude/sessions"

  opencode:
    enabled: true
    # Path to OpenCode session data (JSON files)
    path: "~/.opencode/sessions"
```

## Provider Configuration

Each provider block has the same shape: an `enabled` flag and an optional `path` override. If `path` is omitted, Peasant uses the default location for that provider.

**Supported providers:**

| Provider | Format | Default Detection |
|---|---|---|
| `claude-code` | JSONL | Auto-detected |
| `opencode` | JSON | Auto-detected |

<Callout type="info">
The schema reserves `codex` and `gemini` as future provider identifiers. These are not yet functional.
</Callout>

## Selection Index

The selection index controls which sessions are included during ingestion:

```yaml
selection:
  mode: all  # or "selected"
```

- **`all`** — Ingest every session discovered by the configured providers.
- **`selected`** — Only ingest sessions that have been explicitly selected or tagged.

## Data Paths

Peasant stores its database and sync data under the XDG data directory:

```yaml
# These are the defaults — override only if needed
data:
  path: "~/.local/share/peasant"
```

| File | Purpose |
|---|---|
| `peasant.db` | SQLite database with all ingested session data |
| `peasant-sync/` | Sync artifacts for village push operations |

## Overriding Config at Runtime

You can point Peasant at a different config file for any command using the `--config` flag:

```bash
peasant ingest --config /path/to/alternate-config.yaml
```

This is useful for testing configuration changes without modifying your primary config, or for running multiple Peasant instances against different data sets.

## Example: Minimal Config

A minimal configuration that ingests only Claude Code sessions:

```yaml
providers:
  claude-code:
    enabled: true
  opencode:
    enabled: false

selection:
  mode: all
```

## Example: Custom Paths

A configuration with explicit paths for both providers:

```yaml
providers:
  claude-code:
    enabled: true
    path: "/home/user/my-claude-data"
  opencode:
    enabled: true
    path: "/home/user/my-opencode-data"

data:
  path: "/home/user/.peasant-data"
```
